# porto v0.41 release notes

## Major fixes

### Security

- gRPC-Web CORS now requires an enabled `cors` block and an explicit allowed origin. For both REST and gRPC-Web, an enabled CORS block with an empty origin list now allows none; set `allowed_origins: ["*"]` to retain the old wildcard behavior (and `enabled: true` if enabling gRPC-Web CORS). `Start` now returns an error when an enabled `cors` block combines `allowed_origins: ["*"]` with `allow_credentials: true`; credentialed CORS needs explicit origins or origin patterns. While `cors` is enabled, `Start` also rejects `Access-Control-*` names in `http_headers`; move those settings into the `cors` block. Disallowed gRPC-Web POSTs receive HTTP 403; disallowed preflights receive no allow-origin header. REST requests from disallowed origins still reach their handlers without CORS headers, so REST CORS is not CSRF protection. Configured exposed headers are preserved without duplicate names.

- B10: `marshal.WriteJSON` no longer echoes the text of plain or gRPC-status errors that become 5xx responses; clients receive the generic HTTP status text (for example `Internal Server Error`) and the original error is logged as the cause with the caller's file and line. Identity mapper failures are answered with a generic `invalid identity` 401 (`Unauthenticated` over gRPC); a mapper can still return an `*httperror.Error` to send a deliberate message. `restserver/authz` no longer skips `OPTIONS` requests: preflight headers are caller-controlled, so CORS preflights are answered by the CORS middleware, which `restserver.NewMux` now places outside authz (gserver already did), and every other `OPTIONS` request, including passed-through preflights, is authorized like any method. Denied and not-ready REST responses now carry CORS headers.

- B12/B13: `redisclient.NewRedisClient` no longer logs the Redis URL, which may embed a password; it logs the address and database. `redisclient` and `cache.NewRedisProvider` no longer repeat the URL in the error for a malformed URL. A key containing `..` can no longer leave its prefix: `redisclient.RedisClient.Key` and the cache providers clean a key as a rooted path before joining it with the prefix, so `Key("../other/x")` under `/tenant-a/` is `/tenant-a/other/x` (previously `/other/x`), and a `cache.NewProxyProvider` prefix cannot leave its parent's namespace. Under a prefix, a lock or rate-limit key whose `..` segments would leave its `lock:` or `ratelimit:` namespace (for example `x/../../data`, which previously named the data key `data`, or `a/../b`) is rejected with an error. `Keys` and `ScanKeys` escape glob metacharacters in the prefix, so a prefix such as `ns*` no longer lists keys of sibling prefixes.

- Redact credential headers from retriable HTTP client debug dumps. Token and DPoP key writes now use private temporary files and replace existing credential paths atomically; newly created credential folders use mode `0700`.

- B15: `transport.TLSInfo` no longer has the `AllowedCN`, `AllowedHostname`, `EmptyCN`, `ServerName`, `InsecureSkipVerify` and `SkipClientSANVerify` fields. They were documented but never enforced, so a server that set them could accept clients they were meant to reject. Code that sets them now fails to compile (see Breaking changes).

- B16: `retriable` `WithTLS` and `WithDNSServer` no longer modify the transport they are given: they install a modified clone, so `WithTransport(http.DefaultTransport)` followed by `WithDNSServer` no longer reroutes DNS for every `http.DefaultTransport` user in the process. On a transport that is not an `*http.Transport` they fail closed instead of panicking: `New` returns the error, and after `New` every request fails with it until `WithTransport` replaces the transport, so such a call can no longer be skipped silently. `RequestURL` rejects URLs with user info instead of building a wrong URL from them. Error response bodies are read up to 64 KiB (previously without limit) and bodies of retried responses are drained up to 64 KiB and closed. Retry warnings redact URL passwords.

- B17: HTTP request metrics (`http_requests_perf`, `http_requests_role`) no longer take label values from the request, so callers can no longer create unbounded metric series with random paths or methods. The `uri` label is the matched route template (for example `/v1/users/:id`) or `unknown`; previously it was the raw URL path for every status except 404, including authz 401/403 denials. The `verb` label maps any non-standard method to `_OTHER`.

- B19: `gserver/roles` cookie authentication now needs the CSRF double-submit check on gRPC and gRPC-Web calls too: the `x-csrf-token` metadata (the `X-CSRF-Token` header for gRPC-Web) must equal the `cookies.csrf` cookie on every call. Previously a call authenticated by the auth cookie over gRPC had no CSRF check. `roles.New`, and so `gserver.Start`, rejects `cookies.auth` without `cookies.csrf` when JWT is enabled; HTTP previously ignored the auth cookie then without notice. CSRF errors, which are logged, no longer contain the header and cookie values, and with `debug_logs` the gRPC metadata dump redacts `authorization`, `proxy-authorization`, `cookie`, `dpop` and `x-csrf-token`. AWS4 lookup errors no longer carry the presigned URL (a bearer credential): transport and URL parse errors keep only their cause and the STS host.

- B27: `retriable.New` no longer drops `ClientConfig.TLS` when an option replaces the transport. It applies the configured client certificate and trusted CA after the options, to a clone of the transport they leave, so `New(cfg, WithTransport(t))` trusts the configured CA and sends the configured certificate. Previously the client used `t` as is, usually with the system roots and no client certificate, without an error. When the supplied transport is not an `*http.Transport`, `New` now returns `unable to apply TLS configuration: ...`. A `WithTLS` option still takes precedence when no later `WithTransport` replaced it.

- B23: `tlsconfig.UpdateCipherSuites`, and so `transport.TLSInfo.CipherSuites` and the `gserver` `server_tls.cipher_suites` list, now reject the cipher suites Go lists in `tls.InsecureCipherSuites` with `insecure TLS cipher suite "<name>"`. In Go 1.27 these are the RC4, 3DES and CBC-SHA256 suites and every `TLS_RSA_*` (RSA key exchange) suite; previously a listed suite was enabled without notice. The accepted names are derived from `tls.CipherSuites` of the Go release the binary is built with instead of a hand-maintained table, and `GetCipherSuite` reports only accepted names.

### Concurrency, deadlocks and panics

- TLS certificate reloads now load files outside the handshake lock. The reloading HTTP transport keeps one TLS config and selects the current client certificate for each handshake; it clones a supplied `http.Transport` and closes idle connections after rotation and on `Close`.

- Synchronize retriable client setters and token refresh; missing or public-only DPoP signing keys now return errors.

- Make discovery registration and lookup safe for concurrent use; nil services now return an error, and iteration callbacks may register services.

- `httperror.Error.WriteHTTPResponse` and `ManyError.WriteHTTPResponse` no longer modify the error they write, so `Error` values can be shared across requests, and `ManyError` releases its lock before writing; the readiness 503 is built per request and always carries the current `request_id`. `httperror.Wrap` no longer panics when the first message value is not a string.

- Synchronize scheduler and task state, and make repeated `Stop` calls safe. A stopped scheduler can be restarted.

- `tasks.Scheduler.Stop` no longer lets the scheduler dispatch a task after it returned: a tick that was already due when `Stop` closed the run could still dispatch tasks. Dispatch now re-checks the scheduler state under its lock and marks a dispatched task running before `Stop` can return, so every run dispatched before `Stop` is already counted by `RunCount` and reported by `Task.IsRunning` until it finishes (its callback may still begin executing just after `Stop` returned). This holds for tasks created by `tasks.New` and `tasks.NewTask*`; the scheduler calls `Run` of a custom `Task` implementation on a new goroutine, so such a run may begin, and become visible, after `Stop` returned.

- B11: `cache` subscriptions no longer leak a goroutine per cancelled or timed-out `ReceiveMessage`, and an abandoned receive no longer consumes the next published message. Redis subscriptions read through go-redis `PubSub.Channel`, which also reconnects and resubscribes after connection loss. Memory `Publish` no longer blocks on a subscriber that stopped draining. `ReceiveMessage` now returns as soon as its context is done (previously polled once per second) and returns `cache.ErrClosed` after `Close`, which is idempotent and unblocks a pending receive.

- B12: `redisclient` locks are owner-bound: `TryLock` returns a random token and `ReleaseLock` deletes the lock only while it still holds that token, in one Lua script, so an owner whose lock expired no longer releases its successor's lock. `TryAcquireRateLimit` is a single `SET NX PX`: two concurrent callers can no longer both be allowed in one window, and denied calls no longer extend the window (a caller polling faster than the window was denied forever). `SAddWithEviction` and `HSetWithEviction` update the collection and its order list atomically in one Lua script. `RedisClient.Close` no longer clears the embedded client, which raced with concurrent commands and made later calls panic.

- B07: `gserver.Server.Close` no longer blocks when a listener's setup failed after `Start`; `serve` starts no server until its TLS listener is ready and always closes the channel `Close` waits on. `Close` now stops the TLS certificate reloader, which previously leaked one goroutine per `Start`/`Close` cycle, and runs its teardown once: services are closed once, and a repeated or concurrent `Close` returns after the first teardown has finished (previously a second call closed the services again). A failed `Start` now releases everything on every error path: the reloader is stopped, services created by earlier factories are closed when a later factory fails or is missing, and the cleanup no longer depends on a shadowed error variable. `configureListeners` now really closes the listeners it opened before a later listen URL failed (its previous deferred cleanup read a result that the error return had already reset, so the first listener stayed bound) and stops the reloader it started.

- B15: keepalive listeners (`transport.NewKeepAliveListener`) no longer panic when the wrapped listener returns a connection without TCP keepalive support (for example a Unix socket); the connection is returned without keepalive.

- B16: `retriable` transport setters (`WithTLS`, `WithDNSServer`, `WithTransport`, `WithTimeout`) are safe while requests are in flight: `Do` uses a copy of the HTTP client taken when it starts. A replaced transport that the client created has its idle connections closed (the previous in-place changes reused one pool, whose connections kept the old TLS settings); a transport passed to `WithTransport` is never closed by the client. `WithTLS`/`WithDNSServer` no longer panic on a transport that is not an `*http.Transport` (see Security).

- B19: `credentials.Bundle` per-RPC credentials read the DPoP signer and the `CallerIdentity` provider under the lock their setters take (`WithDPoP` and `WithCallerIdentity` raced with RPCs), and concurrent RPCs that find the token expired share one `GetCallerIdentity` call instead of each making one. `WithCallerIdentity` during a refresh discards the old provider's result, so RPCs started after it use the new provider. A provider that returns a nil token without an error fails the RPC instead of panicking; when a provider panics, the panic reaches the RPC that made the call and the RPCs waiting for it fail with `caller identity provider panicked`. `UpdateAuthToken` and refreshes store a copy of the token's `Expires`.

- B21: the closer returned by `appinit.Metrics` now stops the CloudWatch publishing goroutine: it cancels `cloudwatch.Sink.Run` and returns after `Run` published the last interval (bounded by the sink's 10s shutdown timeout; a failed publish is logged). Previously `Close` flushed once and the goroutine kept publishing for the life of the process. An interval is lost when `Close` aborts a periodic publish in flight or meets a tick `Run` has not handled yet; when `Run` already stopped on expired or missing credentials, `Close` publishes nothing. With `runtime_metrics: true` and a Prometheus or CloudWatch sink, the closer also signals the runtime stats collector to stop; it previously kept stopping the world every second for the life of the process. `Metrics` now returns a closer for that setting even for Prometheus without an address.

- B29: `roles.New`, called by every `gserver.Start`, no longer leaks a goroutine and its cache. Successful STS lookups are now kept in a bounded cache whose entries expire when read, instead of an expirable LRU whose cleanup goroutine was never stopped.

- B27: `retriable` `WithTransport((*http.Transport)(nil))` selects `http.DefaultTransport`, like `WithTransport(nil)`; the nil pointer previously panicked in the first request, or in a later `WithTLS` or `WithDNSServer`.

- B30: a `retriable` client no longer hangs after its `CallerIdentity` provider panics. The requests waiting for that token refresh fail with `caller identity provider panicked`, the panic continues on the request that called the provider, and the next request calls it again. Previously every later request waited until its context ended, or forever without a deadline.

### Correctness and interoperability

- Return REST server HTTP bind errors from `StartHTTP`, support `Config()` and IPv6 bind addresses (`HostName()` returns IPv6 hosts without brackets; `GetServerURL` and `GetServerBaseURL` add them), and make `StopHTTP` safe before start and on repeated calls.

- Route `unix:///path` and `unixs:///path` gRPC client endpoints through the Unix socket resolver without appending a TCP port.

- Sign a fresh DPoP proof for each retry attempt.

- Forward a normalized correlation ID from HTTP requests to gRPC metadata, including the `x-request-id` alias when present.

- Honor gzip quality values for JSON responses, skip compression below 1 KiB, and add `Vary: Accept-Encoding`. Compressed JSON and unary gRPC-Web responses now reuse gzip writers.

- B12: `SAddWithEviction` and `HSetWithEviction` return errors from every step (they were ignored after the first write); re-adding an existing member or updating a field no longer appends a duplicate order entry that later evicted the re-added member, and a member removed with `SRem`/`HDel` and added again no longer meets its stale order entry; a lower limit evicts down to it in one call; a wrong-type key fails before anything is written. The root `RedisClient.Close` returns the close error and is idempotent; commands on a closed client and its `WithPrefix` children return `redis.ErrClosed`. `TryLock` reports the remaining lock time with millisecond precision, and it and `GetRateLimitRemainingTime` report at least 1ms while the lock or window exists (Redis reports 0 during its last millisecond), so 0 means none is active. `ScanKeys` treats a negative limit as the default 1000, as documented. `WithPrefix` cleans its prefix, so `SubKey` and `Keys` work for prefixes such as `a//b`.

- B13: cache `Keys` has one contract on every provider: a Redis glob pattern relative to the provider, returning unexpired keys relative to the provider that `Get` accepts (names written by other clients that no key maps to are skipped, and the key `""` is listed only for an empty pattern). The memory provider now matches with the Redis glob rules (previously only a trailing wildcard, as a prefix match) and no longer lists expired entries.

- `cache.GetOrSet` now stores a successful getter result using the provider's default TTL, reports invalid getter types without panicking, and returns cache write errors.

- B15: `pkg/transport` listeners return accept errors unwrapped, so net/http, grpc and cmux retry temporary errors such as `EMFILE` (too many open files) instead of stopping. Previously the keepalive listener wrapped the error, which made `gserver`'s cmux loop, and with it every server on that address, stop for good. The TLS listener (`transport.NewTLSListener`) likewise stopped accepting after its first accept error and then returned that error on every `Accept`; it now passes each error to one `Accept` call, keeps accepting, and stops when the wrapped listener returns `net.ErrClosed` or when it is closed itself. A wrapped listener that reports its closure with another error (a cmux listener does) keeps the TLS listener's accept loop running until its `Close`; net/http and grpc close the listener when they stop, but other callers must close it. After `Close`, `Accept` returns an error wrapping `net.ErrClosed`. `gserver` now waits between failed accepts (5ms doubling to 1s, reset after a successful accept, each failure logged as a warning) before cmux retries them, so descriptor exhaustion neither stops the server nor spins its accept loop.

- B15: a failed `TLSInfo.ServerTLSWithReloader` call (expired certificate, unknown cipher suite, reloader error) no longer caches the half-built config: a later call, or `NewTLSListener`, returned it without an error and without certificate reloading. A retry now loads the files again. When `ServerTLSWithReloader` fails, `NewTLSListener` leaves the listener it was given open, as before; that is now documented.

- B16: `retriable` clients keep the default 5 retries when a `request:` config block sets only `timeout` (an omitted `retry_limit` previously disabled retries). `DefaultPolicy` now retries 429 as it always declared (up to 3 times), waiting for the server's `Retry-After` or 1s without one, and returns a 429 at once when `Retry-After` asks for more than 30s; `ShouldRetry` consults a `Retries[429]` entry. The wait between retries ends when the request context is done (it previously slept its full length), and, while the context is live, a retry that could not start before its deadline is skipped, returning the last response. `Request` and the helpers release their `RequestTimeout` context when the response is closed instead of at the deadline. The nonce cache drops its oldest nonces when full (it previously dropped the newest cached one). `RequestURL` derives the path from the parsed URL, fixing URLs whose escaped host is longer than the decoded one and IPv6 zone literals. `WithUserAgent` no longer blocks up to one second without a network interface. `NewStorage` expands `~` with the standard library (`$HOME`, else the user database) instead of the archived go-homedir. `DecodeResponse` returns a read error of an error response body instead of the partial body text. `DefaultPolicy` documentation now states the real retry counts (connection errors are retried up to 4 times).

- B17: `telemetry.ResponseCapture`, which `restserver` and `gserver` put twice around every REST handler, now implements `Unwrap` and `http.Hijacker`, so WebSocket upgrades and `http.ResponseController` (read/write deadlines, full duplex, flush) work behind both servers; previously `http.ResponseController` returned `http.ErrNotSupported` and an `http.Hijacker` assertion failed. `Flush` also reaches a flusher behind writers that only implement `Unwrap`, and the new `FlushError` lets `http.ResponseController.Flush` report a failed flush (previously it always returned nil through the capture). `telemetry.NewRequestLogger` no longer panics with a division by zero when the granularity is 0 or negative; the duration is then logged in nanoseconds.

- B19: `credentials.Bundle.NewWithMode` returns an error instead of `(nil, nil)`, as a `grpccredentials.Bundle` must for an unsupported mode. Per-RPC credential errors are wrapped as `unable to get caller identity: ...` and `unable to sign DPoP proof: ...`.

- B21: `appinit.CPUProfiler` returns an error when the profile cannot start, instead of a closer for a profile that never started. A second call while a profile it started runs fails with `CPU profile already running` before it creates (and so truncates) the file; when a profile started otherwise is running, the call fails after creating the file and removes it, and concurrent calls fail with `CPU profile already running` until the removal completes. The file is closed on every path, and the closer's `Close` stops the profile, closes the file and returns the close error. The `--wait-on-exit` help text no longer reads "wait on exist".

- B23: the `transport.TLSInfo.CipherSuites`, `gserver` `TLSInfo.CipherSuites` and `tlsconfig.UpdateCipherSuites` comments no longer say the list order is the server's preference order. Go ignores the order of `tls.Config.CipherSuites` and picks the preferred mutually supported suite itself, so reordering `cipher_suites` never changed the negotiated suite; the list only restricts the enabled TLS 1.2 suites.

- B28: the HTTP request metrics (`http_requests_perf`, `http_requests_role`) now also count responses sent before the metrics handler ran. These are identity mapper rejections (401) in both servers, and `gserver` CORS preflights and rate-limit 429s, including the 429s of throttled gRPC and gRPC-Web calls on TLS listeners. Such responses are labelled `uri="unknown"` and `role="guest"`. A `telemetry.NewRequestMetrics` nested inside another no longer records the request a second time: it passes the role of its request's identity to the outer handler, which records the request once. Both servers now place one metrics handler outside the identity handler and one inside it. `telemetry.ResponseCapture` implements `io.ReaderFrom`, so `http.ServeContent` and `http.FileServer` behind either server keep the sendfile path on plain TCP listeners. In a benchmark serving an 8 MiB file through the telemetry chain, throughput rose from about 3.3 GB/s to 4.8 GB/s.

### Tests and tooling

## New features and behaviour

- B06: shared `xhttp/limits` defaults bound HTTP header reads (10s), whole-request reads (30s), idle keepalive connections (60s), cmux detection and eager TLS handshakes (10s). Header deadlines follow native net/http semantics; HTTP/2 has no per-stream header deadline. Request bodies default to 10 MiB, including standalone `marshal.DecodeBody`. Unknown-length bodies and trailing bytes are bounded too; `RequestTooLarge` now returns HTTP 413. `marshal.LimitRequestBody` writes no response: a known oversized body fails on its first read, so the 413 from `DecodeBody` carries CORS and correlation headers and appears in request logs and metrics. Native gRPC streams on TLS listeners are exempt from the read deadline, so long-lived client and bidi streams are not cut after 30s.
- B11: cache pub/sub delivery is at most once and `Publish` never waits for a subscriber: each subscription buffers 100 undelivered messages (previously 10 for memory); the memory provider drops messages for a full subscriber and Redis follows the go-redis channel policy (a message is dropped after its reader waited one minute). Redis `Subscribe` waits for the server to confirm the subscription, bounded by the context (otherwise by the go-redis dial timeout plus 10s), so a message published after `Subscribe` returns is delivered; a subscription that could not be established returns the wrapped error from `ReceiveMessage` (the context error when the wait was cancelled), and `Publish` errors name the channel.
- Prometheus binds synchronously, returns bind errors without terminating the process, and returns a closer that shuts down its HTTP endpoint. Its endpoint also uses the shared read/body limits.
- B15: keepalive listeners set TCP keepalive with `SetKeepAliveConfig`: probes start after 30s idle, are sent every 15s, and a peer is dropped after 9 unanswered probes (165s). These are the values Go 1.27 produced before; they are now explicit and apply even when the wrapped listener disabled keepalive. A failure to set the options is logged at DEBUG and does not fail `Accept`.

- B16: `retriable.RetryAfterShouldRetryFactory(limit, wait, maxWait, reason)` retries after the response's `Retry-After` (delay-seconds or HTTP date) and stops when it exceeds `maxWait`; register it for 429 or 503 in custom policies. `NonceProvider.NonceContext(ctx)` fetches a nonce bounded by the caller's context; `Nonce()` now bounds its fetch by 30s. `xhttp/header` adds `RetryAfter`, `XClientHostname` and `XClientIP`.

- B17: `telemetry.SetRoute(ctx, pattern)` records the route template for the request metrics; the `restserver` Router calls it for every route, and custom routers behind `telemetry.NewRequestMetrics` can call it with their registered pattern. `telemetry.UnknownRoute` and `telemetry.OtherMethod` name the fallback label values.

- B19: `gserver/roles` caches STS rejections of an AWS4 token for 30s, so a repeated bad token no longer calls STS each time: 4xx responses except 408, 429 and throttling (STS throttles with HTTP 400 and code `Throttling`), and undecodable responses. Transport errors, timeouts, throttling and 5xx are not cached. Concurrent requests with the same uncached token share one STS call; if it panics, the requests waiting for it fail with `STS lookup panicked`. The CSRF check ignores spaces around the cookie value as it did around the header value. `xhttp/header` adds `XCSRFToken`.

## Breaking changes: what clients must change

- B06: raise or disable read/body limits for large uploads and long request streams using `gserver.Config.Timeouts`/`MaxRequestBody`, REST `WithTimeouts`/`WithMaxRequestBody`, or Prometheus `timeouts`/`max_request_body`. Zero selects defaults and negative values disable individual limits. `restserver.MaxRequestSize` is now enforced and is 10 MiB (previously an advisory 64 MiB). Native plaintext gRPC retains per-message limits; TLS gRPC/gRPC-Web request streams receive HTTP body limits, and a native gRPC stream on TLS fails with `Unavailable` after `max_request_body` bytes in total. Handlers that read bodies without `DecodeBody` must map `*http.MaxBytesError` themselves; a known oversized body is no longer answered with 413 before the handler runs. Native net/http TLS handshakes use the smaller positive header/read deadline; `Handshake` configures cmux and eager transport handshakes. Handle `appinit.Metrics` initialization errors and close its returned resource. Sinks still initialize once per process.

- B10: `restserver/authz` now denies an authenticated role with 403 `forbidden` (`codes.PermissionDenied`); an empty or `guest` role still receives 401 `unauthorized`, now `codes.Unauthenticated` over gRPC. The denial message is `<role> role not allowed` without the previous `request <id>: unauthorized:` prefix; the request ID stays in `request_id`. `httperror` maps `codes.PermissionDenied` to 403 (was 401) and `CodeUnauthorized` to `codes.Unauthenticated` (was `PermissionDenied`), so 401 and 403 round-trip through gRPC. Clients matching 401 for denied-but-authenticated calls, or `PermissionDenied` for `httperror.Unauthorized`, must match 403 / `Unauthenticated` instead. REST `OPTIONS` requests other than CORS-answered preflights now need authorization; with `OptionsPassthrough`, application OPTIONS handlers on restricted paths need a permitted role. Custom `WithMuxFactory` chains must place CORS outside authz themselves.

- `httperror.CodeRequestTooLarge` now maps to gRPC `ResourceExhausted` (was `InvalidArgument`), matching grpc-go's oversized-message code. `Error.GRPCStatus` and `ManyError.GRPCStatus` attach an `@httperror.code` status detail beside `@correlation.id`, and `NewFromPb`, `Wrap` and `Status` use it to restore HTTP 413 `request_too_large`; a bare `ResourceExhausted` still converts to 429. gRPC clients that matched `InvalidArgument` for oversized requests must match `ResourceExhausted`. An `Error` whose code has no gRPC mapping now returns a status with code OK instead of nil when it carries a request ID.

- `KeypairReloader` now returns an error for an expired certificate at initial load or reload, and `Reload` returns an error after `Close`. Its TLS callbacks return an error if the current certificate expires; `Keypair` returns nil. `TLSInfo.ServerTLSWithReloader` also routes handshakes without SNI through that callback, so its returned config no longer exposes a static `Certificates` entry. Rotate certificates before expiry and handle reload and handshake errors. TLS constructors also reject CA files with no valid certificate. `NewHTTPTransportWithReloader` now clones a supplied transport; callers should use the returned `HTTPTransport` for requests and close it when done.

- `restserver.StopHTTP` now drains active requests before calling `Service.Close`. Services that must stop accepting work earlier can use a `ServerStoppingEvent` handler. After the shutdown timeout, services still close even if handlers have not finished.

- B07: `gserver.Start` now rejects an enabled `rate_limit` block whose `requests_per_second` is not positive (previously one request per client was admitted and every later one got 429), whose `expiration_ttl` is negative or shorter than one second (an expired bucket is recreated with a full burst), whose `headers_ip_lookups` contains a name other than `RemoteAddr`, `X-Forwarded-For` or `X-Real-IP` spelled exactly, or whose `metods` contains an entry that is not a single upper-case HTTP method token, such as `get`, `"GET "` or `GET,POST` (tollbooth ignored other names and methods and limited nothing). `Config.Validate` and the new `RateLimit.Validate` report the same errors.

- `rpcclient.New` now rejects a TLS configuration paired with `http://`, `unix://`, or a bare endpoint. Change the endpoint to `https://` or `unixs://` to keep TLS and per-RPC credentials enabled.

- `Scheduler.List` now returns a copy of its slice, `Task.Schedule` returns a snapshot, and `New(s)` copies its input schedule. Use `Add`/`Clear` and `SetNextRun`/`UpdateSchedule` to change live state; mutating returned values or the original `s` no longer changes the scheduler or task.

- B11: cache subscribers must expect message gaps under load instead of a blocked publisher, and check `ReceiveMessage` errors: `cache.ErrClosed` after `Close`, the context error when it is done, and a subscribe failure for a Redis subscription that could not be established (re-subscribe to recover). A Redis `ReceiveMessage` no longer returns connection errors: go-redis reconnects and resubscribes in the background and messages published meanwhile are lost; closing a memory or Redis provider closes its subscriptions, whose `ReceiveMessage` then returns `cache.ErrClosed`; a `Subscribe` during or after the provider's `Close` returns a failed subscription reporting `cache.ErrClosed` on both providers (a memory provider previously kept accepting subscriptions after `Close`), and `Subscription.Close` may wait for an in-flight redial during an outage. `Close` discards buffered messages on both providers and releases a go-redis reader blocked on a full buffer at once. Memory `Publish` with an already-done context now returns its error.

- B12: `redisclient.DistributedLock.TryLock` returns `(token string, remaining time.Duration, err error)` and `ReleaseLock` takes that token: replace `ok, remaining, err := c.TryLock(...)` with `token, remaining, err := c.TryLock(...)`, test `token != ""` and call `c.ReleaseLock(ctx, key, token)`. An empty token is an error, and a release after the lock expired returns false. Locks taken by earlier versions cannot be released by a token; they expire, except those taken with a zero timeout, which never expire and must be deleted manually (`DEL <prefix>lock:<key>`). Lock timeouts and rate-limit windows below 1ms return an error (a zero lock timeout previously created a lock without expiry). `ratelimit:<key>` is now a string key and `ratelimit_window:<key>` is no longer written: during a rolling upgrade, an earlier version's `TryAcquireRateLimit` returns a `WRONGTYPE` error while a newer version holds the window and also resets the window's expiry to its own window, so while earlier versions keep polling no caller is allowed; a window left by an earlier version denies newer callers until it expires. Finish the upgrade, or stop the earlier callers, to resume. `SAddWithEviction` and `HSetWithEviction` reject a limit below 1 and identical collection and list keys, keep the position of re-added members, and need a server that allows Lua scripting, like `ReleaseLock`. Under a prefix, lock and rate-limit keys with `..` segments that leave their namespace return an error. Adding a new member or field to a bounded collection scans its order list, so its cost grows with the limit. `RedisClient.Close` can now return an error.

- B13: cache `Keys` returns keys relative to the provider: the memory and proxy providers previously returned full prefixed names, and the Redis provider under a prefix without a trailing slash returned keys with a leading `/`; callers that stripped prefixes themselves must stop. Patterns are Redis globs on the memory provider too (`*` and `?` match `/`). A key whose `..` segments previously climbed above the key's first segment (such as `../x`, or `../app/x` under `/app/`, in `redisclient` or `cache`) now resolves inside the prefix, so data written through such a key is no longer reachable by it; all other keys keep their stored names.

- `cache.GetOrSet` now writes on a cache miss. Callers that require a read without a cache write should use `Get` and their getter directly. On a miss, the destination must point to a concrete type; interface destinations return an error because their values cannot round-trip reliably across providers.

- B15: remove any use of `transport.TLSInfo.AllowedCN`, `AllowedHostname`, `EmptyCN`, `ServerName`, `InsecureSkipVerify` and `SkipClientSANVerify`; they never had any effect. To enforce a client certificate policy, call `TLSInfo.ServerTLSWithReloader` and set `VerifyConnection` on the returned config before calling `transport.NewTLSListener` (the listener uses the same config). Callers that compared the TLS listener's `Accept` error after `Close` with the wrapped listener's own error should use `errors.Is(err, net.ErrClosed)`. `gserver.Server.Listeners` now holds accept-backoff wrappers for every address, including Unix sockets (previously `*net.UnixListener`); code that type-asserted them must use `Addr` and `Close` only.

- B16: in a `retriable` `request:` block (`RequestPolicy`), `retry_limit: 0` or an omitted `retry_limit` now keeps the default 5 retries; write `retry_limit: -1` to disable retries. Default clients now retry 429 responses up to 3 times after `Retry-After` (1s without it; the `gserver` rate limiter sends none, so its 429 is retried after 1s); to keep returning 429 at once, use a policy without a 429 entry (`delete(p.Retries, http.StatusTooManyRequests)` on a `DefaultPolicy()` copy). `NonceProvider` implementations must add `NonceContext(ctx context.Context) (string, error)`. `New` returns an error, and requests fail, when `WithTLS` or `WithDNSServer` is applied to a transport that is not an `*http.Transport` (previously a panic); configure TLS and DNS on the `*http.Transport` before wrapping it. A transport passed to `WithTransport` is no longer changed by later `WithTLS`/`WithDNSServer` calls, and a `*tls.Config` passed to `WithTLS` is copied by a later `WithTLS` or `WithDNSServer` call; code that modified either after configuring the client must configure the client again. `RequestURL` returns an error for URLs without a scheme, opaque URLs (`https:host/path`) and URLs with user info. `Do` with a live context whose deadline is shorter than the next retry wait returns the last response at once (previously it slept the full wait, possibly past the deadline, and then returned the context error); a context cancelled during the wait returns `<METHOD> <URL>: waiting to retry: context canceled`. `X-CLIENT-HOSTNAME` and `X-CLIENT-IP` are omitted, not sent empty, when they cannot be resolved. An error response body longer than 64 KiB is truncated in the returned error.

- B17: dashboards, alerts and recording rules on `http_requests_perf` and `http_requests_role` must select route templates instead of raw paths (for example `uri="/v1/users/:id"` instead of `uri=~"/v1/users/.*"`). Requests that no route handled are counted under `uri="unknown"`, including authz 401/403, readiness 503, `restserver` CORS preflights and the router's 405 and redirect responses, and custom methods under `verb="_OTHER"`. A 404 from a matched route keeps its template, and every 404 now also records a latency sample. `gserver` `WithMiddleware` handlers that answer requests themselves (for example a grpc-gateway mux or static files) and handlers of custom `restserver` mux factories that are not `restserver` Router routes are labelled `unknown` unless they call `telemetry.SetRoute` with their registered pattern.

- B19: set `cookies.csrf` wherever `cookies.auth` is set with JWT enabled, or `roles.New` and `gserver.Start` return `cookies: csrf is required when auth is set`. gRPC and gRPC-Web clients that authenticate with the auth cookie must send the CSRF cookie and `X-CSRF-Token` (`x-csrf-token` metadata) with its value on every call, and cross-origin browser clients must add it to `cors.allowed_headers`; without it the call gets the TLS certificate identity or the guest identity. An AWS4 token that STS rejected returns `cached STS lookup failure: <error>` for 30s, including one signed with an access key that IAM has not propagated yet. AWS4 transport errors read `unable to get Caller Identity from AWS host <host>: <cause>`. Code matching the CSRF error texts must match `CSRF token mismatch` and `missing X-CSRF-Token`.

- B21: `config.CloudWatch.AdditionalTags` and `ReplaceTags` (`add_tags`, `replace_tags`) were removed; they were never applied. Delete them from Go code and from configs read with a strict decoder, which now rejects them. The CloudWatch endpoint key is now `aws_endpoint`, like `aws_region`. The untagged field was read from `awsendpoint` in YAML and `AwsEndpoint` in JSON (in any letter case); lenient decoders now ignore those keys, so the endpoint falls back to the default AWS endpoint, and strict decoders reject them. Rename the key.

- B23: remove insecure suites (see Security) and TLS 1.3 suite names from `cipher_suites`, or building the TLS config fails. Go always enables its TLS 1.3 suites and ignores them in `tls.Config.CipherSuites`, so a listed TLS 1.3 name now returns `TLS 1.3 cipher suite "<name>" is not configurable`. The `TLS_ECDHE_{RSA,ECDSA}_WITH_CHACHA20_POLY1305` alias names are still accepted. A later Go release that moves a suite to `tls.InsecureCipherSuites` makes configs naming it fail after the toolchain upgrade.

- B27: `retriable.New` with `ClientConfig.TLS` and a `WithTransport` option now uses the configured TLS files on a clone of that transport. Code that relied on the transport's own `TLSClientConfig` must drop `ClientConfig.TLS` or pass a later `WithTLS` option. A transport that is not an `*http.Transport` (for example an instrumented wrapper) can no longer be combined with `ClientConfig.TLS`, because `New` returns an error; configure TLS on the wrapped `*http.Transport` and leave `ClientConfig.TLS` unset.

- B28: `http_requests_perf` and `http_requests_role` now include identity 401s, and in `gserver` CORS preflights and rate-limit 429s (all as `role="guest"`, `uri="unknown"`), so alerts on 401 or 429 counts and per-role totals rise. Custom mux factories that nest `telemetry.NewRequestMetrics` now get one sample per request instead of one per handler. To count identity rejections in a custom chain, place a `NewRequestMetrics` on each side of `identity.NewContextHandler`.
